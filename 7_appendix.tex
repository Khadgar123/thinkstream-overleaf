\section{Prompts, Rewards, and Training Details}
\label{app:implementation}

\paragraph{Prompt contract.}
WTI uses the same message contract for SFT, RL rollout, and evaluation.
Each current visual turn contains the timestamp \texttt{<t=N>}, the current 1-second video chunk, an optional \texttt{<active\_query>} block, and an optional \texttt{<response\_history>} block.
Historical state is carried as compact memory lines \texttt{<m t="start-end">summary</m>}.
If a trajectory resumes from compact memory, these \texttt{<m>} lines appear in a separate user turn, followed by the assistant acknowledgement \texttt{Memory loaded.}; the next user turn then starts with \texttt{<t=N>} and current frames.
This keeps prompt-side state aligned with the bounded KV-window rollout: current chunks are visual, while older evidence is either memory text or retrieved by recall.

\paragraph{System instruction.}
The streaming system prompt requires exactly one action per assistant turn.
The assistant must open with \texttt{<think>...</think>} and then end with one terminal action: \texttt{</Silence>} when no query is ready, \texttt{</Response> answer} when the active query is answerable, or a Qwen tool call to \texttt{recall}.
The prompt states that recall is exceptional: it is allowed only when the active query needs older visual evidence that is strictly earlier than the current chunk and is not already available from current frames, compact memory, response history, or a previous recall result.
For future/proactive questions, the prompt explicitly instructs the model to stay silent until the requested visual trigger or event completion is observed.

\paragraph{Tool and output schema.}
Streaming turns expose only the recall function.
Its arguments are absolute source-video seconds, \texttt{start\_time} and \texttt{end\_time}, defining a closed interval \([\texttt{start\_time},\texttt{end\_time}]\) that must be earlier than the current chunk.
Compression is not a callable tool in the active protocol; compact-memory turns output bare \texttt{<m>} lines only.
Thus the parser accepts four canonical outputs: silence, response, recall-tool, or compact-memory \texttt{<m>} lines.
Malformed outputs, multiple terminal actions, future-looking recall intervals, and unsupported tool names are marked as format/action errors.

\paragraph{Compact-memory prompt.}
At a compression boundary, the user payload contains \texttt{OLD\_MEMORY}, \texttt{NEW\_CAPTIONS}, the covered latest span, and instructions to preserve useful old memory while covering new captions with honest time ranges.
The compact-memory system prompt requires the model to return only XML memory lines of the form \texttt{<m t="start-end">one concise English summary</m>}.
It forbids JSON, Markdown, answers, analysis, and tool calls, and it instructs the model to merge adjacent complete units rather than repartition old ranges.

\paragraph{Masked SFT details.}
Masked SFT uses the same bounded state as inference.
The vision encoder is frozen, while the language model and multimodal projector are updated.
Supervision is applied only to assistant-generated tokens; stream inputs, user queries, and environment observations are context only.
We average losses separately over action tokens and state-update tokens, then combine them with the bucket-weighted objective in Section~4, so frequent silence/state-update spans do not dominate action learning.

\paragraph{Stream-GDPO details.}
Stream-GDPO starts from the SFT checkpoint and runs in the same chunk-level streaming environment used at inference.
Each rollout contains one video stream with one or more timed questions.
Question-level rewards cover answer outcome, format validity, and recall use, while the compact-memory reward is computed at the rollout level because memory quality is not tied to a single question.
The policy is optimized on assistant action turns with group-normalized trajectory advantages.

\paragraph{Hyperparameters.}
WTI is initialized from Qwen3-VL-8B-Instruct.
For SFT, we train chunk-level trajectories with the vision encoder frozen, update the language model and multimodal projector, and use learning rate \(1\times10^{-5}\).
For Stream-GDPO, we train for about 60 optimization steps with veRL on 8 H20 GPUs, prompt batch size 64, 4 rollouts per prompt, actor learning rate \(1\times10^{-5}\), asymmetric clipping \(\epsilon_{\mathrm{low}}=0.2\), \(\epsilon_{\mathrm{high}}=0.28\), and action-branch loss weight 0.15.
Videos are streamed as 1-second chunks at 2 FPS, and compact-and-reprefill is triggered when the active context reaches its boundary.

\section{Artifact, Compute, and Responsible Use Details}
\label{app:responsible_use}

\paragraph{Artifacts and licenses.}
We use public pretrained models, benchmarks, and software packages for research training and evaluation, including Qwen3-VL-8B-Instruct~\citep{qwen3vl2025}, StreamingBench~\citep{streamingbench2024}, OVO-Bench~\citep{ovobench2025}, Video-MME~\citep{videomme2025}, MLVU~\citep{mlvu2024}, LongVideoBench~\citep{longvideobench2024}, and veRL/HybridFlow~\citep{sheng2024hybridflow}.
We cite the original creators of the pretrained models, benchmarks, baselines, datasets, and toolkits used in the paper, and follow their corresponding access terms and licenses.
ChronoInteract-82K is intended for research on streaming video reasoning; any public release is subject to source-artifact terms and institutional approval.
It should not be used for surveillance, biometric identification, or safety-critical decision making.

\paragraph{Data screening and privacy.}
The constructed data is derived from public video-derived sources and benchmark materials.
We filter videos for clear visual content and temporally locatable events, and remove examples that fail QA-quality or causal-grounding checks.
Because public video data may contain identifiable people or sensitive scenes, downstream users should preserve the research-only use case and avoid attempts to identify individuals.
The study does not involve recruited human subjects, paid annotators, or new human-subject data collection.

\paragraph{Compute and implementation.}
The main WTI model has 8B parameters and is trained from Qwen3-VL-8B-Instruct.
SFT freezes the vision encoder and updates the language model and multimodal projector; Stream-GDPO is run on 8 H20 GPUs with the hyperparameters in Appendix~\ref{app:implementation}.
The reported Stream-GDPO run used about 60 optimization steps, with each step taking roughly 55 minutes on 8 H20 GPUs, for approximately 440 H20 GPU-hours.
This accounting covers the main RL training run and excludes data generation, benchmark evaluation, and auxiliary diagnostics.
We use veRL for reinforcement learning and source or official benchmark protocols for evaluation when available.
Online evaluations are causal and do not expose future frames; offline long-video evaluations use the aggregate metrics of the source benchmarks.

\paragraph{AI-assisted data construction.}
As described in Section~4 and Appendix~\ref{app:data_stats}, Qwen3.5-397B is used to generate candidate questions, reference answers, and causal-consistency checks during ChronoInteract-82K construction.
The authors verify the generated data, trajectories, claims, citations, and experimental results, and take full responsibility for the paper content.
